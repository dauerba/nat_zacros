# Developer Guide: Caching and Results Pattern

This document describes the "Manager-Worker" architectural pattern used in `nat_zacros` for calculating ensemble properties with automated parameter-aware caching.

## The Hierarchy

- **Lattice**: Geometry and PBC logic.
- **State**: Snapshot of site occupations.
- **Trajectory**: Time-sequence of states (Low-level).
- **Simulation** (The "Worker"):
    - Calculates ensemble statistics across multiple trajectories (e.g., RDF, Energy, Accessibility).
    - **Responsibility**: Perform the heavy math and write results to disk with a standard header.
- **SimulationSet** (The "Manager"):
    - High-level interface for sets of simulations (e.g., across temperatures/coverages).
    - **Responsibility**: Orchestrate the set, validate caches, and only call "Workers" when params change.

---

## Results Files Caching

To ensure that calculations are only re-run when parameters change, we use a standardized header in result files.

### 1. Standard Header Format
All cached property files (e.g., `energy.dat`, `rdf.dat`) MUST start with this line:
```text
# Parameters: key1=val1 key2=val2 ...
```
This is generated by `Simulation.get_ensemble_X(..., file=path)` using `np.savetxt(..., header=f'Parameters: ...')`.

### 2. Parameter-Aware Validation
In `SimulationSet._get_ensemble_property_generic`:
1. **Manager** reads the first line of the existing cache file.
2. **Manager** tokenizes the `# Parameters:` line.
3. **Manager** compares these "cached" values to the "requested" parameters.
4. If they match: Load from disk.
5. If they mismatch: Tell **Worker** to recalculate and overwrite the file.

## How to Add a New Property

To add a new property:


1. **In `Simulation_Set` class**:
   - Add entry to dictionary `self._properties` (property key: property_function). For example, `'cluster': 'get_ensemble_clusters'`

2. **In `Simulation` class**:
   - Implement the corresponding `get`-method. For example, `get_ensemble_clusters(self, pars_dict=None, file=None)`.
   - Parameters necessary for calculating the property should be given in the form of dictionary `{parameter: value}`. For example, 
        ```
        {'cutoff': self.lattice.get_nn_distance(order=3), 
                'fraction': 1.0,
                'method':   'ckdtree'}
        ```
   - Ensure it writes the `# Parameters: ...` header if `file` is not None.

3. **In `Simulation_Set` class**:
  - If visualisation desired, create plot functions. For example, `plot_cluster`



## Benefits
- **Zero-effort caching**: New properties get parameter-aware caching "for free" once the generic handler is used.
- **Robustness**: Changing a parameter automatically triggers a recalculation.
- **Portability**: Cache files are self-documenting; you can see exactly which parameters produced a `.dat` file just by reading its first line.
